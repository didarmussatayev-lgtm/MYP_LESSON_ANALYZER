# MYP Lesson Analyzer — веб-приложение

Загружаете два аудиотрека урока (петличка учителя + общий трек с телефона) и
план урока в браузере → сервер обрабатывает через Gemini API → скачиваете
готовый Word-отчёт. Без локальной ML-модели, без GPU, лёгкий сервер.

**Что это НЕ делает**: не идентифицирует отдельных учеников по голосу
(агрегированная роль "Student"), не даёт точных таймкодов слайдов (только
оценка по текстовому сходству), не заменяет решение методиста/коуча — это
AI-assisted черновик для рефлексии.

## 1. Архитектура (коротко)

```
Браузер (app/static/index.html)
   │  multipart upload: 2 аудио + план урока + опц. pptx
   ▼
FastAPI (app/main.py)
   │  создаёт job, кладёт в фоновую очередь (ThreadPoolExecutor)
   ▼
src/pipeline.py
   │  1. sync.py       - синхронизация треков по времени (локально, бесплатно)
   │  2. gemini_transcribe.py - транскрипция обоих треков (Gemini API)
   │  3. align.py       - слияние в Teacher/Student по таймкодам (локально)
   │  4. slides.py       - опционально: сопоставление слайдов (локально)
   │  5. llm_analysis.py - классификация вопросов/inquiry-level/alignment/
   │                       рефлексия (Gemini API, текстовые вызовы)
   │  6. report.py       - заполнение Word-шаблона (локально)
   ▼
docx-отчёт → скачивание через GET /jobs/{id}/download
```

Локальный Whisper убран из веб-пути: транскрипция происходит на стороне
Gemini, сервер остаётся лёгким и умещается в дешёвый Railway-план.

## 2. Стоимость (ориентир, обязательно перепроверить актуальные цены)

- **Сервер (Railway)**: Hobby-план, минимум $5/мес + фактическое потребление.
  Сервис лёгкий (нет тяжёлой ML-модели), должно укладываться в $5/мес при
  умеренной нагрузке (несколько уроков в неделю).
- **ИИ (Gemini API)**: транскрипция 80 минут аудио (2×40 мин) ≈ $0.12 на
  Gemini 2.5 Flash + классификация/рефлексия (текст) ≈ $0.02-0.05 сверху.
  Итого ≈ $0.15-0.20 за урок. При 20 уроках/мес — около $3-4/мес.
- Обязательно используйте **платный** API-ключ Gemini, не бесплатный ключ
  из AI Studio — на бесплатном тарифе Google может использовать переданные
  данные для обучения моделей, это неприемлемо для записей голосов детей.

## 4. Локальный запуск (проверить перед деплоем)

```bash
cd myp_lesson_analyzer
python3 -m venv venv
source venv/bin/activate
pip install -r requirements-web.txt

export GEMINI_API_KEY="AIza..."   # платный ключ, см. п.2

cd app
uvicorn main:app --reload --port 8000
```

Откройте `http://localhost:8000` — форма загрузки должна появиться. Загрузите
короткий (1-2 минуты) тестовый фрагмент аудио перед полным уроком — так
дешевле поймать проблемы с ключом/квотами/форматом файла.

**Проверено в разработке этого проекта** (без реального GEMINI_API_KEY):
приложение поднимается, страница отдаётся, `POST /jobs` создаёт задачу и
корректно доходит до вызова Gemini, `GET /jobs/{id}` отдаёт статус и
понятную ошибку (не 500 без объяснений), если ключ не задан. Сама
транскрипция через Gemini не тестировалась вживую — нет доступа к
API-ключу в этой среде разработки. Обязательно протестируйте с реальным
ключом на коротком фрагменте перед использованием с настоящим уроком.

## 5. Деплой на Railway через GitHub

### 5.1 Запушить в GitHub

```bash
git init
git add .
git commit -m "MYP lesson analyzer web app"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
git push -u origin main
```

Проверьте `.gitignore` перед коммитом — он уже настроен так, чтобы не
закоммитить аудиофайлы и рабочие директории (`work/`, `output/`,
`uploads/`) — это важно для приватности (голоса детей).

### 5.2 Подключить репозиторий в Railway

1. railway.app → New Project → **Deploy from GitHub repo** → выбрать репозиторий.
2. Railway увидит `Dockerfile` в корне и `railway.toml` — соберёт образ автоматически.
3. Settings → Variables → добавить `GEMINI_API_KEY` (платный ключ).
4. Первый деплой запустится сразу после подключения; следующие — автоматически при каждом `git push` в `main`.

### 5.3 Проверить после деплоя

Railway выдаст публичный URL (`https://<project>.up.railway.app`). Откройте
его в браузере — должна открыться форма загрузки. Загрузите короткий тестовый
фрагмент перед полным уроком.

## 6. Ограничения текущей версии (важно понимать)

- **Состояние задач в памяти процесса.** `JOBS` в `app/main.py` — обычный
  Python-словарь. При рестарте контейнера (деплой, падение, Railway
  перезапуск) все запущенные/завершённые задачи "забываются" — уже
  сгенерированные docx-файлы на диске никуда не денутся, но статус задачи
  через `/jobs/{id}` вернёт 404. Для личного использования одним учителем
  это приемлемо; для нескольких одновременных пользователей стоит
  перенести состояние в БД (Postgres на Railway — отдельный лёгкий плагин).
- **Один воркер обработки одновременно** (`ThreadPoolExecutor(max_workers=1)`)
  — задачи выполняются по очереди, не параллельно. Осознанное упрощение:
  для одного учителя с несколькими уроками в неделю параллелизм не нужен;
  увеличьте `max_workers`, если планируете нескольких одновременных
  пользователей (но тогда учтите нагрузку на Gemini API квоты).
- **Файлы не защищены авторизацией.** Любой, кто знает URL сервиса и
  `job_id`, может скачать отчёт. Для реального использования с чужими
  данными добавьте базовую аутентификацию (даже просто пароль на форму)
  перед тем, как давать ссылку другим людям.
- **Слайды пока не встроены в итоговый docx** — `slides.py` считает
  таймлайн, но `report.py`/шаблон его не выводят в документ (см. TODO в
  предыдущей версии README, актуально и сейчас).

## 7. Приватность (обязательно перед реальным использованием)

- Нужно согласие школы/родителей на аудиозапись урока и на передачу записи
  в облачный ИИ-сервис (Gemini API — данные уходят за пределы вашей
  инфраструктуры).
- `app/main.py` удаляет аудиофайлы сразу после обработки урока (см.
  `_run_job` → `finally`) — не расширяйте срок хранения без явной причины.
- Используйте платный API-ключ (см. п.2) — принципиально для privacy.
- Отчёт явно маркирован в шаблоне как "AI-assisted draft... not a formal
  performance evaluation" — не убирайте этот дисклеймер.
