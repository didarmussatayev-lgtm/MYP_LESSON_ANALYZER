# MYP Lesson Analyzer — веб-приложение

Загружаете два аудиотрека урока (петличка учителя + общий трек с телефона) и
план урока в браузере → сервер обрабатывает через Gemini API → скачиваете
готовый Word-отчёт. Без локальной ML-модели, без GPU, лёгкий сервер.

**Что это НЕ делает**: не идентифицирует отдельных учеников по голосу
(агрегированная роль "Student"), не даёт точных таймкодов слайдов (только
оценка по текстовому сходству), не заменяет решение методиста/коуча — это
AI-assisted черновик для рефлексии.

## 1. Архитектура (коротко)

```
Браузер (app/static/index.html)
   │  multipart upload: 2 аудио + план урока + опц. pptx
   ▼
FastAPI (app/main.py)
   │  создаёт job, кладёт в фоновую очередь (ThreadPoolExecutor)
   ▼
src/pipeline.py
   │  1. sync.py       - синхронизация треков по времени (локально, бесплатно)
   │  2. gemini_transcribe.py - транскрипция обоих треков (Gemini API)
   │  3. align.py       - слияние в Teacher/Student по таймкодам (локально)
   │  4. slides.py       - опционально: сопоставление слайдов (локально)
   │  5. llm_analysis.py - классификация вопросов/inquiry-level/alignment/
   │                       рефлексия (Gemini API, текстовые вызовы)
   │  6. report.py       - заполнение Word-шаблона (локально)
   ▼
docx-отчёт → скачивание через GET /jobs/{id}/download
```

Локальный Whisper убран из веб-пути: транскрипция происходит на стороне
Gemini, сервер остаётся лёгким и умещается в дешёвый Railway-план.

## 2. Стоимость (ориентир, обязательно перепроверить актуальные цены)

- **Сервер (Railway)**: Hobby-план, минимум $5/мес + фактическое потребление.
  Сервис лёгкий (нет тяжёлой ML-модели), должно укладываться в $5/мес при
  умеренной нагрузке (несколько уроков в неделю).
- **ИИ (Gemini API)**: транскрипция 80 минут аудио (2×40 мин) ≈ $0.12 на
  Gemini 2.5 Flash + классификация/рефлексия (текст) ≈ $0.02-0.05 сверху.
  Итого ≈ $0.15-0.20 за урок. При 20 уроках/мес — около $3-4/мес.
- Обязательно используйте **платный** API-ключ Gemini, не бесплатный ключ
  из AI Studio — на бесплатном тарифе Google может использовать переданные
  данные для обучения моделей, это неприемлемо для записей голосов детей.

## 3. Структура проекта

```
myp_lesson_analyzer/

├── requirements-web.txt        # зависимости веб-приложения (без Whisper)
├── requirements.txt            # зависимости для локального CLI-варианта (с Whisper, опционально)
├── config/taxonomy.yaml        # редактируемые критерии классификации
├── templates/lesson_report_template.docx   # Word-шаблон с Jinja-тегами
├── src/
│   ├── common.py                # общие структуры данных
│   ├── sync.py                  # синхронизация треков (без ИИ)
│   ├── gemini_transcribe.py     # транскрипция через Gemini (используется веб-версией)
│   ├── transcribe.py             # локальный Whisper (опционально, для CLI без интернета)
│   ├── align.py                  # роли Teacher/Student по таймкодам
│   ├── slides.py                  # сопоставление слайдов (без ИИ)
│   ├── llm_analysis.py            # классификация/рефлексия через Gemini
│   ├── report.py                  # генерация Word-отчёта
│   └── pipeline.py                # оркестратор, используется и CLI, и веб-приложением
└── app/
    ├── main.py                    # FastAPI: upload, фоновая очередь, статус, скачивание
    └── static/index.html          # форма загрузки
```

## 4. Локальный запуск (проверить перед деплоем)

```bash
cd myp_lesson_analyzer
python3 -m venv venv
source venv/bin/activate
pip install -r requirements-web.txt

export GEMINI_API_KEY="AIza..."   # платный ключ, см. п.2
export ADMIN_EMAIL="you@school.edu"      # первый администратор (создаётся при первом запуске)
export ADMIN_PASSWORD="длинный-пароль"

cd app
uvicorn main:app --reload --port 8000
```

Откройте `http://localhost:8000` и войдите под ADMIN_EMAIL / ADMIN_PASSWORD.
Учителей добавляет администратор в разделе «Пользователи» (самостоятельной
регистрации нет). Загрузите
короткий (1-2 минуты) тестовый фрагмент аудио перед полным уроком — так
дешевле поймать проблемы с ключом/квотами/форматом файла.

**Проверено в разработке этого проекта** (без реального GEMINI_API_KEY):
приложение поднимается, страница отдаётся, `POST /jobs` создаёт задачу и
корректно доходит до вызова Gemini, `GET /jobs/{id}` отдаёт статус и
понятную ошибку (не 500 без объяснений), если ключ не задан. Сама
транскрипция через Gemini не тестировалась вживую — нет доступа к
API-ключу в этой среде разработки. Обязательно протестируйте с реальным
ключом на коротком фрагменте перед использованием с настоящим уроком.

## 5. Деплой на Railway через GitHub

### 5.1 Запушить в GitHub

```bash
git init
git add .
git commit -m "MYP lesson analyzer web app"
git branch -M main
git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
git push -u origin main
```

Проверьте `.gitignore` перед коммитом — он уже настроен так, чтобы не
закоммитить аудиофайлы и рабочие директории (`work/`, `output/`,
`uploads/`) — это важно для приватности (голоса детей).

### 5.2 Подключить репозиторий в Railway

1. railway.app → New Project → **Deploy from GitHub repo** → выбрать репозиторий.
2. Railway увидит `Dockerfile` в корне и `railway.toml` — соберёт образ автоматически.
3. Settings → Variables → добавить:
   - `GEMINI_API_KEY` — платный ключ;
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` (и по желанию `ADMIN_NAME`) — первый
     администратор. Используются только пока в базе нет ни одного
     пользователя; после первого входа пароль лучше сменить в «Профиле».
4. **Подключить Volume** (Service → Settings → Volumes → New Volume,
   mount path `/data`). Образ хранит базу, отчёты и файлы в обработке в
   `DATA_DIR=/data`. Без Volume всё это стирается при каждом редеплое.
5. Первый деплой запустится сразу после подключения; следующие — автоматически при каждом `git push` в `main`.

### 5.3 Проверить после деплоя

Railway выдаст публичный URL (`https://<project>.up.railway.app`). Откройте
его в браузере — должна открыться страница входа. Загрузите короткий тестовый
фрагмент перед полным уроком.

## 6. Как устроено веб-приложение

- **Вход и роли.** Email + пароль, серверные сессии (cookie HttpOnly,
  30 дней). Роли: учитель (видит только свои уроки) и администратор
  (видит все уроки, управляет пользователями, видит технические детали
  ошибок). После 5 неверных паролей вход для email блокируется на 5 минут.
- **Хранилище.** SQLite-файл в `DATA_DIR` (`app/db.py`): пользователи,
  сессии, уроки со статусом, журналом и структурированными результатами
  анализа. Отдельный сервер БД не нужен.
- **История уроков и веб-отчёт.** Отчёт открывается прямо на сайте:
  показатели, распределение времени речи, типы вопросов, шкала уровней
  inquiry, план и факт, расшифровка с поиском (таймкоды кликабельны).
  Word-отчёт по-прежнему скачивается, есть печать/PDF из браузера.
- **Надёжность обработки.** Если сервер перезапустился посреди анализа,
  урок автоматически продолжится с последнего завершённого этапа
  (промежуточные результаты лежат в `DATA_DIR/work`). При ошибке
  пользователь видит понятное сообщение и кнопку «Повторить» — расшифровка
  повторно не оплачивается.
- **Предметы.** Все 8 предметных групп MYP и междисциплинарный юнит
  (`config/subject_frameworks.yaml`, данные из официальных гайдов IB):
  критерии оценивания со strands (MYP year 5), related concepts (по
  дисциплинам/фазам), key concepts предмета, пометки о том, какие критерии
  не наблюдаются по аудио. Для выбранных критериев отдельный этап анализа
  показывает, по каким strands урок давал ученикам возможность проявиться
  (вкладка «Критерии» веб-отчёта; в Word-отчёт пока не выводится).
- **Запись урока на сайте** (`app/recordings.py`, раздел «Записать урок»).
  Браузер пишет звук через MediaRecorder и каждые 10 секунд отправляет
  кусок на сервер; при обрыве связи куски ждут в очереди и досылаются.
  Если запись прервалась (заблокировали экран, закрыли вкладку), она
  продолжается новым сегментом той же записи. По завершении сервер через
  ffmpeg склеивает всё в один mono mp3 и подставляет его в новый анализ.
  «Карманный режим» — чёрный экран + Wake Lock, чтобы телефон не засыпал.
  Ограничение браузеров: при блокировке экрана кнопкой питания iPhone
  останавливает запись, Android — иногда; настоящая фоновая запись при
  заблокированном экране возможна только в нативном приложении.
- **Автозаполнение плана** (`src/planner.py`, `POST /api/planner/extract`):
  unit planner в .docx / .pdf / тексте → Gemini → поля формы. Значения из
  справочников (key concept, related concepts, критерии, ATL, learner
  profile) сверяются с конфигом, всё лишнее отбрасывается.
- **Роли.** Учитель — свои уроки; методист (observer) — все уроки и
  динамика, комментарии, без управления пользователями и без удаления
  чужих уроков; администратор — всё.
- **Обсуждение отчёта.** Вкладка «Обсуждение»: комментарии методиста и
  учителя с привязкой к разделу отчёта.
- **Динамика по учителю** (раздел «Динамика», `GET /api/progress`):
  графики по урокам — доля речи учителя и учеников, вопросы высшего
  порядка, время на уровнях inquiry 2+, реализация плана, strands; сравнение
  последнего урока со средним по прошлым.
- **Языки.** Язык урока (подсказка для распознавания речи) и язык выводов
  и рекомендаций (русский / казахский / английский) выбираются в форме.
- **Один воркер обработки** (`ThreadPoolExecutor(max_workers=1)`) — уроки
  обрабатываются по очереди. Увеличьте при большом числе учителей, учитывая
  квоты Gemini.
- **Слайды пока не встроены в отчёт** — `slides.py` считает таймлайн, но
  ни docx, ни веб-отчёт его ещё не показывают.

Переменные окружения: `GEMINI_API_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`,
`ADMIN_NAME`, `DATA_DIR` (по умолчанию `app/`, в Docker — `/data`),
`MAX_UPLOAD_MB` (по умолчанию 500).

## 7. Приватность (обязательно перед реальным использованием)

- Нужно согласие школы/родителей на аудиозапись урока и на передачу записи
  в облачный ИИ-сервис (Gemini API — данные уходят за пределы вашей
  инфраструктуры).
- `app/main.py` удаляет аудиофайлы и промежуточные файлы сразу после
  успешной обработки (`_delete_sources`). Если обработка упала, аудио
  остаётся до повторного запуска или удаления урока — чтобы «Повторить»
  не требовал загружать запись заново.
- Расшифровка урока хранится в базе вместе с отчётом (нужна для веб-отчёта).
  Удаление урока на сайте стирает её, отчёт и все файлы урока.
- Используйте платный API-ключ (см. п.2) — принципиально для privacy.
- Отчёт явно маркирован в шаблоне как "AI-assisted draft... not a formal
  performance evaluation" — не убирайте этот дисклеймер.

## 8. Калибровка (сделать один раз на реальных данных)

- `src/align.py`: `overlap_threshold` (по умолчанию 0.4) — прогоните на
  реальной 5-минутной записи, проверьте вручную, не теряются ли реплики
  учеников и не остаётся ли эхо учителя неотфильтрованным.
- `config/taxonomy.yaml`: формулировки категорий вопросов/inquiry-level/
  ATL — согласуйте с координатором MYP школы.
